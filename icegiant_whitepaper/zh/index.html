摘要

去中心数据存储网络，如Filecoin、Arweave和Storj，通过创建不可篡改的、安全的存储功能，实现了新一轮的去中心化数据开发基础设施。IceGiant通过NoSQL数据库同步协议扩展了这些数据存储网络提供的功能，IceGiant协议支持快速去中心化开发，并通过使用更丰富的NoSQL数据结构(如哈希、列表、集合)与数据指令来丰富应用系统的数据表达层，提升web3/web2系统对于去中心化网络与数据的使用能力。

1. 介绍

1.1 动机

对于web3领域，目前没有办法像在web2中那样轻松地编写一个完备的客户端应用程序，并且让其实现完全去中心化。在web2中，您在AWS上启动一个数据库，并让您的客户端应用程序调用该数据库进行读写。但web3中没有类似的东西。不能只将数据写入以太坊，这对于大多数用户来说太昂贵了。Filecoin和Arweave等存储协议主要用于归档数据，但没有为写入和读取数据提供企业级性能保证。

在本文中，我们介绍IceGiant，这是一种新颖的解决方案，可以实现高度可伸缩的、去中心化的NoSQL数据库。通过利用RESP作为主要的交互协议，IceGiant支持快速、复杂、去中心化的开发，同时消除了开发人员学习任何新技能和语言的需求。

利用IceGiant的优势可以分为四个不同的类别：

  1. 大幅缩短开发时间
  2. 增强web3/web2应用的功能和定制
  3. 快速的数据查询速度和加载时间
  4. 增强数据组合、复杂数据使用场景的简易性

首先，分布式NoSQL数据库的实现使得几乎每个开发人员都可以在去中心化架构上进行构建。RESP作为世界流行的Redis数据库的通信协议，现已成为NoSQL数据库的主要通信协议，Redis作为web2环境下市场份额第一位的NoSQL数据库，被世界范围的开发者广泛使用。通过兼容RESP通信协议，IceGiant大大减少了开发时间和技术门槛，从而促进了去中心化应用的开发。

IceGiant还支持开发某些以前在web3中不可能实现的功能，通过为开发人员提供全功能的NoSQL引擎，IceGiant允许开发者在几毫秒内对海量数据集执行复杂的查询。这种级别的优化进一步可以推动web3应用程序进入数据驱动状态，而不要牺牲其产品的去中心化属性。

web3技术的大规模采用的关键是它能够为最终用户提供他们在web2中已经习惯的用户体验，网页的加载时间直接影响商业的转化率，沃尔玛发现页面加载时间每减少1秒，转化数就会增加2％，目前的web3分布式存储的网关加载时间还需要优化，IceGiant的核心目标就是为用户提供快速而且数据结构丰富的NoSQL数据集系统。

最后，IceGiant提供了更丰富的数据表达和数据组合功能，对于目前web3通常仅能KV读写的困境，我们提供Strings\Hashes\Lists\Sorted Sets\Sets数据结构，实现前所未有的应用数据级互操作性。IceGiant支持常规的RESP通信协议，无论开发人员是希望利用应用程序的数据集，还是对于特定的数据片段感兴趣，IceGiant均提供了简单高效的方式来利用数据。

2.系统组成

2.1 网络结构

虽然所有IceGiant节点都在相同的P2P网络中，但是网络的结构可以根据数据集进行分解，数据集是数据租户隔离区域，它是指位于IceGiant协议之上的特定应用程序使用的数据库区域。与传统的区块链网络不同，IceGiant节点只负责和操作相同数据集的对等体进行交互，不负责其他数据集的任何数据，对等IceGiant节点集之间组成高可用数据存储区域。

2.2 存储机制

每个单独IceGiant的NoSQL存储层，主要包括编解码层、底层KV存储层，底层的KV引擎目前支持levelDB、badgerDB、IPFS、OSS，主要数据存储包括两种方式：

  1. 基于IPFS-log指令广播模型
  2. 基于IPFS的原生数据存储模型

具体的存储模型设计会在3.3节NoSQL存储引擎中进一步描述，多个IceGiant节点之间会根据数据集进行群组划分，每个群组范围内形成高可用存储区域结构。

2.2 智能合约

IceGiant主要使用智能合约构建去中心化存储引擎策略中心，我们的目标是构建一个可以自我运转、公共治理的数据库平台，目前智能合约的运行载体主要考虑EVM兼容的虚拟机环境，我们首先选择FVM作为我们的去中心化管理平台，FVM作为FileCoin存储生态的计算层，可以让我们在更贴近数据存储的位置进行可信计算与提供服务，并提供用户更可靠的数据操作可信度。

智能合约功能主要包括：

  1. 数据集与多租户去中心化可信管理
  2. 用户账户与访问凭证管理
  3. NoSQL数据库写入指令集的合约存储，用于数据可信同步与数据一致性验证

2.3 查询结构

在提交给节点的每个查询中，有以下几段不同的数据：

  1. query: Standard RESP protocol query
  2. timestamp
  3. query hash
  4. query id
  5. RSA signature

每次写入数据时，节点都会确保RSA签名对资金池的关联密钥有效，公钥在智能合约中存储。在验证签名之后，节点检查时间戳以确保它落在当前块的有效时间范围内。

一旦时间戳被接受，节点就检查查询ID的唯一性，查询ID由节点保障在当前时间范围内的batch内部不能重复，它可以采用和查询相关联的随机64个字符。如果节点是leader，还需要维护数据库中数据集的当前状态。

3.节点架构

3.1 反向代理

反向代理服务器是发送到节点的所有请求的入口点，在IceGiant节点上，反向代理服务器有四个主要用途:

  1. 管理TLS/SSL证书，确保与任何客户端/对等节点的加密通信。
  2. 实施 CORS(跨源资源共享)配置，规定从哪些 源(客户端和对等端)接受数据读/写。
  3. 将传入请求路由到正确的网关或同步器，并防止绕过任何高级请求网关。
  4. 从本地文件系统提供静态资源。

3.2 IceGiant同步器

IceGiant同步器是直接位于数据库引擎之上的应用程序，所有传入的数据库请求都通过IceGiant同步器，它决定是否应该处理请求，是否应该将数据写入传播到网络的其他部分，以及是否应该写入本地数据并响应客户请求。 IceGiant同步器还可以提供数据写入聚合功能，允许将多个数据请求进行合并并写入单个网络存储请求，也允许用户在不同的节点之间交叉混合数据集，鼓励进一步的数据去中心化，同时保持较低的操作开销。

3.3 NoSQL存储引擎

每个节点的核心是数据库引擎，默认情况下，IceGiant节点融合了levelDB、badgerDB、IPFS、OSS等KV存储引擎，并在KV存储关系上实现了NoSQL的协议编码层，目前对于NoSQL的数据存储，主要包含以下两种方式：

第一种：基于IPFS-log指令广播模型：基于IPFS-log和ctdt实现用于分布式系统的不可变的、基于操作的无冲突复制数据模型，在IPFS-log的基础上封装多种数据结构例如：event、kv等，基于此引擎实现多节点数据库指令广播；在IceGiant底层我们抽象了基于badgerdb、leveldb可变动kv引擎，任何节点在进行写指令操作是会进行全网广播，各个节点IceGiant底层驱动对广播命令进行执行，保障数据最终一致性。

每个IceGiant节点均是一个完善的NoSQL数据库引擎，每个数据库引擎都被配置为只允许通过运行在同一台机器上的IceGiant同步器进行访问，这样做主要有以下考虑：

  1. 限制同步器访问数据库，降低用户出错的机会，非传播数据写入必须被IceGiant同步器明确识别，而不是意外提交给NoSQL数据库存储引擎，这使得网络中相似节点尽量包含相同的数据。
  2. 通过反向代理或其他高级网关限制对于IceGiant同步器的访问，让数据库用户减少攻击媒介，从而减少网络被僵尸程序滥用，数据/隐私泄露以及跨节点状态差异的恶性情况。

3.4 高级请求处理程序

IceGiant节点可以选择配备一个高级请求处理网关，其核心是一个应用程序中间件，可以包含复杂的业务逻辑来定义数据库交互。这可以将IceGiant节点的功能从数据库/数据存储系统，发展成全功能的去中心化API系统。可以构建高级请求网关的样例包括：细粒度的数据库权限访问，复杂的聚合查询和并发查询，以及将哪些数据传递给IceGiant同步器进行传播的规则。

例如，我们可以构建一个多租户管理页面在高级请求网关上运行，该网关管理特定于应用程序的逻辑，此类系统的优势在于，它只需要一个网关验证访问权限。

4. 智能合约

4.1 交易结构

IceGiant块在提交给智能合约时以JSON格式存储，因为每个IceGiant节点能够服务多个数据集，所以单个智能合约事务中可以包含多个块。

在每个JSON中，顶层键是数据所引用的数据集的名称。在第一层键的下面是接收数据写入的请求端点，数据被请求端点分割后，所有数据写入按照时间顺序排序。

4.2 合约交互

数据集存在、所有权和验证的主要功能来自智能合约，主要用于构建数据集隔离、数据读写日志、资金池、数据合法及一致性验证。

5.块索引：跟踪块元数据

5.1 $IFDB令牌

IceGiant及IceGiant生态的原生令牌是$IFDB令牌，该令牌有以下用途：

  1. 令牌的主要目的是让相关方验证数据库的传入块，这可以以利益相关者运行对等验证者节点的形式出现，也可以通过利益委托给验证者的形式出现。
  2. 令牌机制防止网络垃圾请求，由于数据集的名称是唯一的，注册数据集会消耗少量令牌，创建一个小的进入壁垒，对于善意的用户来说可以忽略不计。

5.2销售验证节点程序

IceGiant验证池中的主验证者是具有最高股份/委托股份的节点。这个节点可以由与它所服务的项目密切相关的个人/团体来管理，但是理论上它可以由任何第三方来运行。

lead validator是任何查询被发送到的默认节点，并负责为所有应用程序数据提供服务(这是默认的，但不是强制的)。除了跟踪适当的状态 变化之外，主确认器还运行数据库，该数据库运行数据集的活动状态。将此作为默认设置的好处是，它显著降低了节点维护数据集的总成本。项目可以选择创建更“昂贵”的数据集，从而受益于进一步的去中心化，但是在大多数用例中，任何进一步的去中心化都会导致边际效用递减。

任何拥有或委托给主验证者的股份在验证者最近的区块完成之前不能被取走。一旦一个区块被新的主导验证者开采，主导验证者可以从池中移除他们的股份。lead validator可以在挖掘其最终块时请求取消标记，防止标记被锁定到其角色。

5.3 对等验证器

任何不是领导者的验证者都是对等验证器，默认情况下，对等验证器的职责是跟踪传入的数据写入，并确保这些写入被主验证器正确的存储在IPFS上。

对等验证器也可以选择维护数据库的活动状态，从而使它们能够像主验证器一样被查询。一些网络用户可能需要这样做，因为它可以作为一种机制来消除网络停机的风险。此外，最高级别的验证者可能在维护数据库的活动状态方面有既得利益，因为他们在任何时候成为下一个主要验证者。

6.资金池：多链支持

6.1 EVM多链资金池

资金池使个人和社区能够支付任意数量的区块链的数据使用费用。资金池只是一个为验证者保存资金的智能合约，可以用来激励验证者正确地行动，基金池中的令牌用于支付运营商的存储、计算和硬件成本。

一个数据集可以有任意数量的资金池，创建资金池时，创建者能够制定池所绑定的链、令牌和验证器。这使得用户可以用任何ERC20等价令牌支付到IceGiant网络中。通过允许在任何令牌中进行支付，IceGiant创建了一个与链无关的NoSQL数据库，它利用智能合约作为状态跟踪层。
